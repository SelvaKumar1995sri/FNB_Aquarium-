# Razorpay Account Setup (Test Mode)

This project's online-payment checkout uses Razorpay. Follow these steps to
create a Razorpay account and get the three credentials this backend needs:
`RAZORPAY_KEY_ID`, `RAZORPAY_KEY_SECRET`, `RAZORPAY_WEBHOOK_SECRET`.

Test mode is free and requires no business verification/KYC — it's enough
for local development and demoing the full checkout flow.

## 1. Create a Razorpay account

1. Go to https://dashboard.razorpay.com/signup
2. Sign up with an email and password (or Google sign-in).
3. Verify your email via the link Razorpay sends you.
4. You'll land on the Razorpay Dashboard. You can skip/close any business
   KYC prompts for now — they're only required to accept **live** payments,
   not test payments.

## 2. Switch to Test Mode

- In the dashboard, find the mode toggle (usually top-left, near the logo) —
  set it to **Test Mode**. All the steps below assume you're in Test Mode.

## 3. Generate API keys (`RAZORPAY_KEY_ID` / `RAZORPAY_KEY_SECRET`)

1. Go to **Settings** (left sidebar) → **API Keys**.
2. Click **Generate Test Key**.
3. A popup shows the **Key Id** (starts with `rzp_test_...`) and
   **Key Secret**. Copy both now — the secret is shown only once. If you
   lose it, you'll need to regenerate a new key pair.

## 4. Set up a webhook (`RAZORPAY_WEBHOOK_SECRET`)

The webhook is how Razorpay tells this backend a payment succeeded, so the
order can be auto-marked paid.

1. Go to **Settings** → **Webhooks**.
2. Click **+ Add New Webhook**.
3. **Webhook URL**: point it at this backend's webhook endpoint:
   `https://<your-domain>/api/v1/payments/webhook/`
   - For local development, Razorpay needs a public URL to reach your
     machine. Use a tunnel, e.g.:
     ```
     ngrok http 8000
     ```
     then use the `https://xxxx.ngrok.io/api/v1/payments/webhook/` URL
     ngrok gives you.
4. **Secret**: type any string of your own choosing (e.g. a random
   password) — this is *not* generated by Razorpay, you invent it. Save the
   same value into `RAZORPAY_WEBHOOK_SECRET`.
5. **Active events**: enable at least `payment.captured` (that's the only
   event this backend currently handles — see
   `orders/views.py::RazorpayWebhookView`).
6. Click **Create Webhook**.

## 5. Update `backend/.env`

Replace the placeholder values with your real ones:

```
RAZORPAY_KEY_ID=rzp_test_xxxxxxxxxxxx
RAZORPAY_KEY_SECRET=xxxxxxxxxxxxxxxxxxxx
RAZORPAY_WEBHOOK_SECRET=your_chosen_webhook_secret
```

Restart the backend server after saving so the new values are picked up.

## 6. Test the flow

Razorpay's test mode accepts specific dummy card/UPI details that never
charge real money:

- **Test card**: `4111 1111 1111 1111`, any future expiry date, any CVV.
- **Test UPI**: use `success@razorpay` as the UPI ID to simulate a
  successful payment (`failure@razorpay` to simulate a failure).

Full list of test credentials: https://razorpay.com/docs/payments/payments/test-card-upi-details/

Place a test order through checkout, pay with the test card above, and
confirm the order shows as paid (the webhook should fire and update the
order status automatically).

## Going live later

When ready to accept real payments, complete Razorpay's KYC/business
verification (Settings → Account & Settings), then generate **Live** mode
keys and a **Live** mode webhook the same way, and swap them into
production's environment variables. Never reuse test-mode keys in
production, and never commit real keys to git — `.env` is git-ignored for
this reason.
